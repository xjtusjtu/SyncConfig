# 经管论文写作与修改

目标是产出作者能使用、能追溯、研究含义不被悄悄改变的文本。先判断修改尺度，再决定工作流程；不要把所有请求都变成整篇审稿，也不要把整篇调整缩减为同义词替换。

## 1. 识别任务与材料

从请求和现有材料推断：学科与研究范式、目标语言、修改范围、交付形式、目标期刊（如有）、是否允许实质改动。正文默认保持原语言；反馈默认使用用户交流语言。

- “评价、检查、诊断、建议大纲”只交付诊断或建议，不据此改写原文件。
- “润色”允许改变表达、段内顺序和必要衔接，不默认改变研究问题、理论解释、估计对象或结论。
- “全局调整大纲”允许提出结构与论证重组；是否直接应用，以用户是否要求修改文件为准。
- “扩写”允许展开已有信息和推理，不授权编造事实、补造结果或宣称验证了新机制。
- “增强理论贡献”可以重述已有论证，不能把新情境自动升级为理论创新。

不要为了开始修改而逐项询问完整问卷。仅当缺失选择会实质改变论证或需要发明证据时，询问一个关键问题；其余可完成部分先做。材料只有摘要或一个段落时，不声称已审读整篇论文。

实证研究的原始分析材料通常包含大量探索性分析、稳健性检验与grid search结果。只汇报用户明确指定或原文指定的版本；除非明确说明，探索性结果与未选中规格视为不存在，不补入正文。

动手前先查找并读取**项目写作约定文件**：从稿件所在目录逐级向上寻找最近的 `WRITING_CONVENTIONS.md`，以其中的术语、变量名、样本口径、符号与表图引用为准。论文遵循该约定文件，**不遵循代码或工程实现**。约定文件缺失时报告缺失并继续按本 skill 默认规范工作，不自动创建。详见 [写作约定文件](references/manuscript-conventions.md)。

## 2. 按模式加载规范

先读 [学科与章节规范](references/discipline-and-sections.md) 中对应研究范式与章节；不要仅凭期刊名称强制选择范式。任何模式在改字之前，先按 [写作约定文件](references/manuscript-conventions.md) 定位并读取项目约定，并以 [读者视角表达](references/reader-facing-expression.md) 检查正文是否能让不了解技术背景的审稿人读懂。顶刊写作强调：贡献清晰定位、理论-证据紧密连接、段落逻辑清晰、正面陈述研究发现。

| 模式 | 触发与范围 | 必读规范 | 核心交付 |
|---|---|---|---|
| G1 全局大纲／论证 | 整篇结构、研究主线、章节与贡献重构 | [全局修改](references/global-editing.md) | 主线、章节功能、证据去向、重排方案 |
| G2 全局润色 | 已有全文的表达与跨节一致性 | [全局修改](references/global-editing.md) | 连贯全文、术语一致、有限修改说明 |
| L1 局部润色 | 一段、若干段或指定小节 | [局部修改](references/local-editing.md) | 可直接替换的文本 |
| L2 局部扩写 | 从现有段落／要点展开论证 | [局部修改](references/local-editing.md) | 有实质增量的文本、具体证据缺口 |

混合任务按 G1 → G2 → L1/L2 的必要顺序工作，但只做用户授权的部分。结构调整会导致段落删除时，先处理结构再润色句子。只润色一个段落，不必生成整篇主线表。

涉及数值、因果、机制、引用、新事实或实质修改时，另读 [证据与保护规则](references/evidence-and-integrity.md)。普通语言编辑不要求浏览；新增或纠正文献论断、确认当前期刊规则时必须核对来源。

## 3. 始终保护研究内容

默认固定：研究对象与单位、构念定义、变量及量纲、估计对象、数据版本、样本与时期、系数方向与数值、推断结果、公式、假设与命题、引用键及其支持的论断、图表编号、结论强度、适用范围和关键限制。

保护的是“内容与其归属”，不仅是字符出现次数。两个系数交换对象、引用转移到不支持的论断、删掉否定词，都可能在数字和引用清单不变时改变研究。

发现原文疑似错误或过度宣称时：

1. 定位问题并说明依据。
2. 在仅润色任务中，不悄悄替作者决定实质修改；交付可保留含义的部分，将有问题的句子单独标记并给出建议。
3. 若用户已要求修正错误或校准论断，可按证据修正，并在交付中说明改变了什么含义；缺乏证据时不编造替代结论。

术语与命名以约定文件为准：统一称谓时不改变构念定义、测量口径、量纲、样本口径、估计对象与结论强度。不把代码标识（变量名、列名、函数名、模块名、脚本名）搬进正文；正文使用约定文件登记的正式名称。

保留作者有定义的术语和声音。不是每个长句、被动语态、路标或技术名词都应删除；判断其是否承担论证功能。去除空泛与模板化表达，不以“规避 AI 检测”为优化目标。
局限与边界条件的放置：除非用户明确要求或原文结构明确安排，研究局限、方法局限、数据局限集中放置于论文最后部分的局限讨论中。摘要、引言、理论、方法、结果、一般讨论及附录正文均以正面陈述研究发现与含义为主，保留统计名称、数值、样本与估计对象的准确表述，不反复插入"但这不能证明""仅是相关""未排除X"等防御性限定。正文不以大量括号和防御性限定承载信息；直接影响读者解读某一步骤或结果的限制，就地在方法或结果处用一两句说明。

## 4. 输出与文件操作

- L1/L2：改文在前；仅解释重要含义变化、难以消除的歧义、真实材料缺口。用户要求只给正文时，交付正文；必要风险另行简短说明。
- G1：先给建议主线与大纲，并交代各节功能和证据安排；避免先输出大量微观语法问题。
- G2：交付修订稿或修改文件位置；简述跨节改动和待核对事项。
- 诊断：按影响排序给"位置 → 问题 → 为什么影响论证 → 可行修改"；不凭空打分或预测顶刊录用。
- 用户要求比较稿时提供原文／改文及关键理由；不要默认逐句巨型表格。
- LaTeX 保留数学、命令、引用和交叉引用；Markdown 保留有效结构。不要为润色擅自迁移格式或更换文献管理系统。
- 修改前确认项目与指定文件；保留无关改动。全局调整不得自动改动数据、分析脚本、其他论文或演示文稿。
- 约定文件缺失或与稿件冲突时不静默处理：报告缺失，或列出差异清单（约定写法 ↔ 稿件写法 ↔ 涉及对象），实质差异交用户裁定。

## 5. 交付前检查

按当前模式检查，不要求每次展示检查表：

1. 修改是否仍在用户指定范围，未读材料是否被当成已读？
2. 研究问题、贡献、理论／设计、发现与讨论是否相互一致？
3. 原有事实、限制、否定、量纲、引用归属和结论强度是否保留，实质变化是否说明？
4. 扩写增加的是定义、推理、比较或证据解释，还是没有信息增量的背景句？
5. 改文是否自然、术语一致，是否把必要的不确定性删成确定断言？
6. 缺口是否具体定位，未核实来源是否仍留在正文中冒充文献？
7. 段落是否充实且逻辑清晰：全文最多2～3处极短段落（2～3句），其余段落内容充实、长度相当；段落首句通常为中心句，结尾视情况总结或过渡；章节首段阐明该section动机、目的与大致工作。
8. 局限是否集中表述：除用户明确要求外，局限集中于最后的局限部分，正文与附录正文不主动指出不足。
9. 读者视角：不了解技术背景的审稿人能否读懂？新术语首次出现是否先以普通语言说明其对应的动作或对象？方法步骤是否交代了为什么做—给什么输入—怎样处理—得到什么输出？
10. 命名与表达：正文是否混入代码标识（变量名、列名、函数名、模块名）？是否堆叠连续抽象名词、或以大量括号和防御性限定推进论述？术语是否与约定文件一致？

同语言、保留原意的修改可用词面检查辅助人工复核：

```bash
python scripts/check_protected_fields.py original.md revised.md
```

路径相对本 skill 根目录。临时输入与输出放在项目 `tmp/`。该工具只比较数字、LaTeX 引用、数学片段和交叉引用的词面清单；不能判断语义等价、事实真实性或引用支持关系。全局删除重复内容、扩写和翻译可能合理改变清单，应逐项解释，而非设法让检查器通过。

设计依据、审读版本和不采用的规则见 [来源与取舍](references/sources-and-decisions.md)；仅当需要核对规范来源或维护本 skill 时加载。
